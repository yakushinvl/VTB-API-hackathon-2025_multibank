# Архитектура приложения Мультибанк

## Обзор

Мультибанк - это веб-приложение для агрегации финансовых данных из разных банков через открытые банковские API. Приложение состоит из двух основных частей: backend (Node.js/Express) и frontend (React).

## Backend (Server)

### Технологии

- **Node.js** - среда выполнения
- **Express** - веб-фреймворк
- **SQLite** - база данных
- **JWT** - аутентификация
- **bcryptjs** - хеширование паролей
- **axios** - HTTP клиент для банковских API

### Основные модули

#### 1. `server/index.js`
Главный файл сервера. Настраивает Express, подключает middleware, регистрирует роуты и запускает сервер.

**Ключевые функции:**
- Инициализация Express приложения
- Настройка CORS для работы с frontend
- Подключение роутов API
- Обработка ошибок
- Статические файлы для production

#### 2. `server/models/database.js`
Модуль для работы с базой данных SQLite.

**Таблицы:**
- `users` - пользователи приложения
- `bank_connections` - подключения к банкам (OAuth токены)
- `accounts` - счета пользователей
- `cards` - карты пользователей
- `transactions` - транзакции

**Функции:**
- `init()` - инициализация БД и создание таблиц
- `getDB()` - получение экземпляра БД
- `close()` - закрытие соединения

#### 3. `server/middleware/auth.js`
Middleware для аутентификации и авторизации.

**Функции:**
- `authenticateToken` - проверка JWT токена
- `requireSubscription` - проверка наличия подписки

#### 4. `server/services/bankService.js`
Сервис для работы с банковскими API.

**Поддерживаемые банки:**
- VBank (vbank.open.bankingapi.ru)
- ABank (abank.open.bankingapi.ru)
- SBank (sbank.open.bankingapi.ru)

**Функции:**
- `getBankConfig()` - получение конфигурации банка
- `refreshAccessToken()` - обновление токена доступа
- `getValidAccessToken()` - получение валидного токена
- `makeBankRequest()` - выполнение запроса к API банка
- `syncAccounts()` - синхронизация счетов
- `syncCards()` - синхронизация карт
- `syncTransactions()` - синхронизация транзакций

#### 5. Роуты API

**`/api/auth`** - Аутентификация
- `POST /register` - регистрация пользователя
- `POST /login` - вход в систему
- `POST /logout` - выход
- `GET /me` - текущий пользователь

**`/api/accounts`** - Счета
- `GET /` - список счетов
- `GET /:id` - детали счета
- `GET /:id/transactions` - транзакции по счету
- `POST /sync` - синхронизация счетов
- `POST /:id/transactions/sync` - синхронизация транзакций

**`/api/cards`** - Карты
- `GET /` - список карт
- `GET /:id` - детали карты
- `GET /:id/transactions` - транзакции по карте
- `POST /sync` - синхронизация карт
- `POST /:id/transactions/sync` - синхронизация транзакций

**`/api/transactions`** - Транзакции
- `GET /` - все транзакции с фильтрами
- `GET /:id` - детали транзакции

**`/api/offers`** - Предложения банков
- `GET /` - список предложений с поиском

**`/api/assistant`** - ИИ-помощник (требует подписку)
- `GET /analysis` - анализ трат
- `GET /cashback` - рекомендации по кэшбэку
- `POST /chat` - чат с помощником

**`/api/user`** - Профиль пользователя
- `GET /profile` - профиль
- `PUT /profile` - обновление профиля
- `PUT /password` - изменение пароля

**`/api/banks`** - Банки
- `GET /available` - доступные банки
- `GET /connected` - подключенные банки
- `POST /connect/:bankName` - подключение банка
- `POST /callback` - OAuth callback
- `DELETE /:connectionId` - отключение банка

## Безопасность

### Аутентификация

- Используется JWT (JSON Web Tokens)
- Токены хранятся в HTTP-only cookies
- Срок действия токена: 7 дней
- Пароли хешируются с помощью bcrypt (10 раундов)

### OAuth 2.0

- Поддержка OAuth 2.0 для подключения банков
- Токены доступа хранятся в зашифрованном виде
- Автоматическое обновление токенов при истечении

### Защита данных

- CVV карт скрыт по умолчанию
- Пароли никогда не передаются в открытом виде
- Все API запросы требуют аутентификации (кроме auth)

## Интеграция с банковскими API

### Процесс подключения

1. Пользователь выбирает банк для подключения
2. Приложение генерирует OAuth URL
3. Пользователь перенаправляется на страницу авторизации банка
4. После авторизации банк перенаправляет на callback URL с кодом
5. Приложение обменивает код на токены доступа
6. Токены сохраняются в базе данных

### Синхронизация данных

1. Пользователь инициирует синхронизацию
2. Приложение проверяет валидность токена
3. При необходимости обновляет токен
4. Выполняет запросы к API банка
5. Сохраняет полученные данные в локальную БД

### Обработка ошибок

- Автоматическое обновление истекших токенов
- Обработка недоступности API банков
- Логирование ошибок
- Информирование пользователя об ошибках

## Масштабируемость

### Архитектурные решения

1. **Модульная структура** - легко добавлять новые банки
2. **Абстракция банковского сервиса** - единый интерфейс для всех банков
3. **Кэширование данных** - локальная БД для быстрого доступа
4. **Асинхронная синхронизация** - не блокирует UI

### Добавление нового банка

1. Добавить конфигурацию в `BANKS` объект в `bankService.js`
2. Настроить OAuth параметры
3. Протестировать интеграцию
