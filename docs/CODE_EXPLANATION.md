# Объяснение кода и модулей приложения

## Общая архитектура

Приложение построено по принципу разделения на слои:
- **Presentation Layer** (Frontend) - React компоненты и страницы
- **API Layer** (Backend Routes) - REST API endpoints
- **Business Logic Layer** (Services) - бизнес-логика и интеграции
- **Data Layer** (Models) - работа с базой данных

## Backend модули

### 1. `server/index.js` - Главный файл сервера

```javascript
const express = require('express');
const cors = require('cors');
const cookieParser = require('cookie-parser');
```

**Назначение:** Точка входа приложения, настройка Express сервера.

**Ключевые части:**

1. **Инициализация Express:**
   - Создание приложения
   - Настройка middleware (CORS, JSON parser, cookie parser)

2. **Инициализация БД:**
   ```javascript
   const db = require('./models/database');
   db.init();
   ```
   - Создает соединение с SQLite
   - Создает все необходимые таблицы

3. **Регистрация роутов:**
   - Каждый роут отвечает за свою область функциональности
   - Все роуты префиксированы `/api`

4. **Обработка ошибок:**
   - Глобальный error handler
   - Логирование ошибок
   - Возврат понятных сообщений об ошибках

### 2. `server/models/database.js` - Работа с базой данных

**Назначение:** Абстракция для работы с SQLite базой данных.

**Основные функции:**

1. **`init()`** - Инициализация БД
   - Создает соединение с SQLite
   - Вызывает `createTables()` для создания схемы

2. **`createTables()`** - Создание таблиц
   - `users` - пользователи
   - `bank_connections` - OAuth подключения к банкам
   - `accounts` - счета
   - `cards` - карты
   - `transactions` - транзакции
   
   Использует `db.run()` для выполнения SQL команд.

3. **`getDB()`** - Получение экземпляра БД
   - Проверяет, что БД инициализирована
   - Возвращает экземпляр для использования в других модулях

**Особенности:**
- Использует промисы для асинхронных операций
- Поддержка каскадного удаления (ON DELETE CASCADE)
- Уникальные ограничения для предотвращения дубликатов

### 3. `server/middleware/auth.js` - Аутентификация

**Назначение:** Middleware для защиты маршрутов.

**Функции:**

1. **`authenticateToken(req, res, next)`**
   - Извлекает JWT токен из cookies или заголовка Authorization
   - Проверяет валидность токена с помощью `jwt.verify()`
   - Добавляет информацию о пользователе в `req.user`
   - Вызывает `next()` при успехе или возвращает ошибку

2. **`requireSubscription(req, res, next)`**
   - Проверяет наличие активной подписки у пользователя
   - Используется для защиты премиум-функций
   - Запрашивает БД для проверки `subscription_active`

**Использование:**
```javascript
router.get('/protected', authenticateToken, (req, res) => {
  // req.user содержит информацию о пользователе
});
```

### 4. `server/services/bankService.js` - Интеграция с банками

**Назначение:** Единый интерфейс для работы с разными банковскими API.

**Структура:**

1. **Конфигурация банков (`BANKS`):**
   ```javascript
   const BANKS = {
     vbank: {
       name: 'VBank',
       domain: 'vbank.open.bankingapi.ru',
       baseUrl: 'https://vbank.open.bankingapi.ru',
       authUrl: 'https://vbank.open.bankingapi.ru/oauth/authorize',
       tokenUrl: 'https://vbank.open.bankingapi.ru/oauth/token'
     },
     // ...
   };
   ```

2. **`getBankConfig(bankName)`** - Получение конфигурации банка

3. **`refreshAccessToken(userId, bankConnectionId)`** - Обновление токена
   - Использует refresh_token для получения нового access_token
   - Обновляет токены в БД

4. **`getValidAccessToken(userId, bankConnectionId)`** - Получение валидного токена
   - Проверяет срок действия токена
   - Автоматически обновляет при необходимости

5. **`makeBankRequest(userId, bankConnectionId, endpoint, method, data)`** - Выполнение запроса
   - Получает валидный токен
   - Добавляет заголовок Authorization
   - Выполняет HTTP запрос через axios

6. **`syncAccounts(userId, bankConnectionId)`** - Синхронизация счетов
   - Запрашивает список счетов из API банка
   - Сохраняет/обновляет в локальной БД
   - Использует `INSERT OR REPLACE` для обновления существующих записей

7. **`syncCards()` и `syncTransactions()`** - Аналогично для карт и транзакций

**Обработка ошибок:**
- Автоматическое обновление истекших токенов
- Логирование ошибок
- Возврат понятных сообщений

### 5. Роуты API

#### `server/routes/auth.js` - Аутентификация

**Эндпоинты:**

1. **`POST /api/auth/register`**
   - Валидация данных (email, username, password)
   - Проверка уникальности email/username
   - Хеширование пароля с bcrypt
   - Создание пользователя в БД
   - Генерация JWT токена
   - Установка токена в HTTP-only cookie

2. **`POST /api/auth/login`**
   - Поиск пользователя по email или username
   - Проверка пароля
   - Генерация JWT токена
   - Возврат информации о пользователе

3. **`POST /api/auth/logout`**
   - Очистка cookie с токеном

4. **`GET /api/auth/me`**
   - Проверка токена через middleware
   - Возврат информации о текущем пользователе

**Валидация:**
Использует `express-validator` для проверки входных данных.

#### `server/routes/accounts.js` - Управление счетами

**Эндпоинты:**

1. **`GET /api/accounts`**
   - Получение всех счетов пользователя
   - Опциональная фильтрация по типу (`?type=debit`)

2. **`GET /api/accounts/:id`**
   - Получение конкретного счета
   - Проверка прав доступа (только владелец)

3. **`GET /api/accounts/:id/transactions`**
   - Получение транзакций по счету
   - Поддержка пагинации (`?limit=5`)
   - Опция развертывания (`?expand=true`)

4. **`POST /api/accounts/sync`**
   - Синхронизация счетов с банком
   - Вызывает `bankService.syncAccounts()`

**Безопасность:**
- Все эндпоинты защищены `authenticateToken`
- Проверка прав доступа (только свои данные)

#### `server/routes/cards.js` - Управление картами

Аналогично `accounts.js`, но для карт.

**Особенности:**
- CVV скрыт по умолчанию (`***`)
- Показывается только при явном запросе (`?showCvv=true`)

#### `server/routes/transactions.js` - Транзакции

**Эндпоинты:**

1. **`GET /api/transactions`**
   - Получение всех транзакций пользователя
   - Фильтры: `accountId`, `cardId`, `startDate`, `endDate`
   - Пагинация: `limit`, `offset`
   - Статистика за текущий месяц

**Статистика:**
- Количество транзакций
- Сумма расходов
- Сумма доходов

#### `server/routes/offers.js` - Предложения банков

**Эндпоинты:**

1. **`GET /api/offers`**
   - Получение предложений от всех подключенных банков
   - Поиск по тексту (`?search=...`)
   - Фильтрация по банку (`?bank=...`)

**Логика:**
- Итерируется по всем подключениям пользователя
- Запрашивает предложения от каждого банка
- Агрегирует результаты
- Применяет фильтры

#### `server/routes/assistant.js` - ИИ-помощник

**Эндпоинты:**

1. **`GET /api/assistant/analysis`**
   - Анализ трат за период (неделя/месяц/год)
   - Статистика по категориям
   - Генерация рекомендаций

2. **`GET /api/assistant/cashback`**
   - Анализ трат по категориям
   - Рекомендации по выбору карты для максимального кэшбэка

3. **`POST /api/assistant/chat`**
   - Чат с ИИ-помощником
   - Простая реализация (можно заменить на LLM API)

**Защита:**
- Все эндпоинты требуют подписку (`requireSubscription`)

#### `server/routes/user.js` - Профиль пользователя

**Эндпоинты:**

1. **`GET /api/user/profile`**
   - Получение профиля
   - Список подключенных банков

2. **`PUT /api/user/profile`**
   - Обновление профиля (username, email, avatar, theme, language)

3. **`PUT /api/user/password`**
   - Изменение пароля
   - Проверка текущего пароля
   - Хеширование нового пароля

#### `server/routes/banks.js` - Управление банками

**Эндпоинты:**

1. **`GET /api/banks/available`**
   - Список доступных банков

2. **`GET /api/banks/connected`**
   - Список подключенных банков пользователя

3. **`POST /api/banks/connect/:bankName`**
   - Генерация OAuth URL
   - Возврат ссылки для авторизации

4. **`POST /api/banks/callback`**
   - Обработка OAuth callback
   - Обмен code на токены
   - Сохранение подключения в БД

5. **`DELETE /api/banks/:connectionId`**
   - Отключение банка
   - Удаление подключения из БД

## Frontend модули

### 1. `client/src/App.js` - Главный компонент

**Назначение:** Настройка роутинга и провайдеров.

**Структура:**

1. **`AuthProvider`** - Обертка для контекста аутентификации
2. **`Router`** - Настройка маршрутов
3. **`PrivateRoute`** - Компонент для защиты маршрутов
   - Проверяет наличие пользователя
   - Перенаправляет на `/login` если не авторизован

**Маршруты:**
- Публичные: `/login`, `/register`
- Приватные: все остальные

### 2. `client/src/context/AuthContext.js` - Контекст аутентификации

**Назначение:** Глобальное состояние аутентификации.

**Состояние:**
- `user` - текущий пользователь
- `loading` - состояние загрузки

**Методы:**

1. **`checkAuth()`** - Проверка аутентификации
   - Запрос к `/api/auth/me`
   - Обновление состояния пользователя

2. **`login(login, password)`** - Вход
   - POST запрос к `/api/auth/login`
   - Сохранение пользователя в состоянии

3. **`register(...)`** - Регистрация
   - POST запрос к `/api/auth/register`
   - Автоматический вход после регистрации

4. **`logout()`** - Выход
   - POST запрос к `/api/auth/logout`
   - Очистка состояния

**Использование:**
```javascript
const { user, login, logout } = useAuth();
```

### 3. `client/src/services/api.js` - API клиент

**Назначение:** Конфигурация Axios для работы с API.

**Особенности:**

1. **Базовый URL:**
   ```javascript
   baseURL: process.env.REACT_APP_API_URL || 'http://localhost:5000/api'
   ```

2. **Cookies:**
   ```javascript
   withCredentials: true
   ```
   - Отправка cookies с каждым запросом
   - Необходимо для JWT токенов

3. **Interceptor для ошибок:**
   - Автоматическое перенаправление на `/login` при 401
   - Обработка других ошибок

## Безопасность

### Frontend

1. **JWT токены:**
   - Хранятся в HTTP-only cookies
   - Не доступны через JavaScript

2. **Валидация:**
   - Валидация форм на клиенте
   - Дополнительная валидация на сервере

3. **Защита маршрутов:**
   - `PrivateRoute` компонент
   - Проверка аутентификации

### Backend

1. **Хеширование паролей:**
   - bcrypt с 10 раундами
   - Соль генерируется автоматически

2. **JWT:**
   - Секретный ключ из переменных окружения
   - Срок действия: 7 дней

3. **Валидация:**
   - `express-validator` для всех входных данных
   - Проверка прав доступа

4. **SQL Injection:**
   - Параметризованные запросы
   - Использование `?` плейсхолдеров

## Обработка ошибок

### Backend

1. **Глобальный error handler:**
   ```javascript
   app.use((err, req, res, next) => {
     // Логирование
     // Возврат понятного сообщения
   });
   ```

2. **Валидация:**
   - Возврат списка ошибок валидации
   - HTTP статус коды

### Frontend

1. **Try-catch блоки:**
   - Обработка ошибок в async функциях
   - Отображение сообщений пользователю

2. **Axios interceptor:**
   - Автоматическая обработка 401
   - Перенаправление на login

2. **Кэширование:**
   - Локальная БД для быстрого доступа

3. **Оптимистичные обновления:**

3. Протестировать интеграцию

### Добавление новой функции

1. Создать роут в `server/routes/`
2. Добавить бизнес-логику в `server/services/`
3. Создать страницу/компонент в `client/src/pages/`
4. Добавить маршрут в `App.js`
